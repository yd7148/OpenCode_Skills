# zh-text-polish — 繁中錯字校對與文句潤飾

對繁體中文文件（會議紀錄、公文、技術報告、週報）做三件事：
**錯字訂正 → 文句潤飾 → 專業格式統一**，交付對照表＋修訂全文。

## When to use
- 使用者要求「確認有無錯字」「文句更專業／更通暢」「潤飾這段文字」
- 手上有 OCR／語音辨識殘留 `?`、`□`、`○` 的草稿要清理
- 會議紀錄要轉成正式呈核格式（指示、執行部門、預完日）
- 使用者說「新增一個文句編輯的 SKILL」

## 核心原則
1. **原文保留**：先原樣引用問題句，不改寫成技術語言後再評論。
2. **區分等級**：錯字（必改）／格式（應改）／風格（建議改）三級，不混為一談。
3. **不發明事實**：數字、日期、人名、決議只修格式，不自行增刪。若有疑義列入「待確認」欄，不猜測。
4. **全形統一**：中文文件標點一律全形（，。；：（））；數字與單位之間空半形一格（`0.02 Ω·cm`）；次方用上標或 `10^10` 註明。
5. **單位與縮寫首次展開**：`FAT` → `工廠驗收測試（FAT）`；`tie-in` → `管線銜接（tie-in）`；`TaC` 維持原文但前後一致。

## 常見錯誤檢查清單
- 殘留符號：`?`、`□`、`○`、`...` 多為 OCR／輸入法殘留，逐一確認刪除或還原原意
- 諧音錯字：`問定性`→`穩定性`、`庫版`→`庫板`、`減低`→`降低`
- 數量級：`1010`→`10^10`、`0.02Ω⋅cm`→`0.02 Ω·cm`
- 日期格式：一份文件只用一種（`10月15日` 或 `10/15`，擇一）
- 表格錯位：執行部門／預完日空白列、`11/E` 類無意義字串，需重排為正常表格
- 落款：`職:劉士禎10/12呈` → `記錄：劉士禎　114年10月12日呈`，簽核欄留白需標示

## 工作流程
### 1. 讀完原文
完整讀取使用者貼文或檔案；若是檔案，用 `read` 讀完全文後再動筆。

### 2. 產出校對報告（繁中，必含三要素）
1. **Mermaid 流程圖**：`flowchart TD` 呈現 原文→分類→訂正→驗證 路徑
2. **Markdown 對照表**：欄位固定為 `| # | 原文（原樣） | 問題類型 | 修訂建議 | 說明 |`
3. **修訂全文**：可直接貼回公文的乾淨版本，表格用標準 Markdown 表格

### 3. 儲存與驗證（如需落檔）
- 檔名：`<主題>-<YYYYMMDD>.md`，置於該專案目錄（本 repo 根目錄維運紀錄例：`sic-weekly-proofread-20261012.md`）
- 寫完用 `read` 回讀確認無亂碼、表格直線對齊、`git diff --check` 無行尾警告
- `.md` 行尾一律 LF（見 `.gitattributes`）

## 輸出結構（貼文回覆時）
1. 一句總結：共 N 處（錯字 X／格式 Y／建議 Z）
2. Mermaid 圖（`flowchart TD`）
3. 對照表（見上）
4. 修訂全文（`## 修訂全文` 小節，可直接複製）
5. 待確認事項表（數字／人名／日期有疑義者列此，不代為決定）

## Deliverables checklist
- [ ] 對照表含「原文原樣」欄（非改寫後）
- [ ] Mermaid 圖至少一張
- [ ] 修訂全文可直接使用（無殘留 `?`）
- [ ] 待確認事項獨立成表
- [ ] 落檔時檔名含日期、行尾為 LF
